# 拾念 · Shinian

**留住每一个好想法，从容完成每一件事。**

拾念是独立的桌面灵感与待办工具。它把快速记录、自定义分类、可拖动的卡片、行动看板和本地备份放在同一个安静的工作区。

## Windows 使用方法

1. 下载 `Shinian-1.0.0-Windows-x64.zip`，将整个压缩包解压到一个固定文件夹。
2. 双击文件夹中的 `Shinian.exe`。首次使用不需要安装 Node.js、Python，也不需要登录账号。
3. 在顶部记录框输入一句话，按 **Enter** 保存。分类可以稍后再整理。

这是 Windows 10/11 的 x64 免安装版。请保留 EXE 旁边的资源与 DLL 文件，不能只复制一个 EXE。程序数据保存在系统用户数据目录，默认是 `%APPDATA%\Shinian`，因此移动或替换程序文件夹不会同时删除记录。

应用包未配置商业代码签名，首次启动时系统可能显示未知发布者。请核对同包的 SHA-256 清单和来源，按你电脑的安全策略处理，不需要关闭系统防护。

## 一条灵感的使用过程

- **先记下来。** 默认保存在收集箱。顶部记录框、快捷键 N，以及全局快捷记录都可以开始一条灵感。
- **找到分类。** 点击“我的分类”右侧的 +，自定义名称、颜色和标记。拖动卡片到左侧任意分类；拖回“收集箱”即可取消分类。拖动分类本身可以调整顺序。
- **补充细节。** 点击卡片打开编辑器，可填写正文、标签、优先级、截止日期和子任务。修改后约半秒自动保存；完成编辑会等待保存成功。
- **开始行动。** 把灵感转成待办。看板分为灵感、待办、进行中、已完成，支持拖动卡片改变状态。
- **标记完成。** 点击卡片左上角的完成按钮，或拖到“已完成”。已完成内容可以在左侧“已完成”中查看，也可以重新打开。

## 已有功能

| 区域 | 功能 |
| --- | --- |
| 快速记录 | 中文标题、长正文、灵感/待办切换、草稿保留、全局快捷窗口 |
| 分类 | 自定义名字、预设及自选颜色、图形标记、分类排序、拖动归类、批量移动 |
| 待办 | 未开始、进行中、已完成；截止日期、逾期提示、优先级、子任务 |
| 整理 | 卡片/列表/看板、星标、标签筛选、状态筛选、日期/优先级/标题排序 |
| 查找 | 全局搜索标题、正文和标签，搜索结果可在工作区继续筛选 |
| 安全回退 | 删除先到回收站，可恢复；永久删除需要确认 |
| 数据 | 自动保存、原子写入、最新有效副本、14 个日历日自动备份、导入/恢复前备份 |
| 迁移 | 完整 JSON 备份、Markdown 导出、合并导入、冲突保留副本 |
| 桌面 | 系统托盘、全局快捷键、窗口置顶、可选登录时启动、单实例、多窗口数据同步 |
| 外观 | 浅色、深色、跟随系统；中文字体随应用离线提供 |

第一次启动时没有任何项目或记录。可以选择“先逛逛示例空间”载入明确标注的虚构示例。示例只允许加入完全空白的工作区，可以自由编辑和删除。

## 快捷键

| 快捷键 | 作用 |
| --- | --- |
| N | 在主窗口新建灵感；输入文字时不触发 |
| T | 在主窗口新建待办；输入文字时不触发 |
| Ctrl + K（macOS 为 ⌘ + K） | 搜索与快速导航 |
| Enter | 顶部标题框保存记录 |
| Ctrl / ⌘ + Enter | 保存记录；编辑器保存并关闭 |
| Esc | 关闭搜索；编辑器保存并关闭；快捷窗口隐藏并保留草稿 |
| Ctrl / ⌘ + Alt + Space | 全局快捷记录，要求拾念仍在运行 |
| Ctrl / ⌘ + Q | 彻底退出软件 |

全局快捷键可以在“设置 → 快捷键”中改成其他预设组合或关闭。若被其他软件占用，设置页面会显示未能注册，请选择其他组合。

“关闭窗口后留在托盘”默认开启。Windows 上关闭主窗口后仍能使用快捷记录；要彻底退出，右键托盘图标并选择退出，或使用 Ctrl + Q。托盘不可用时会退出程序，避免留下无法找回的后台窗口。Linux 默认不依赖无法确认的托盘入口。

## 数据保存与恢复

桌面版的数据由主进程统一管理；主窗口和快捷窗口使用同一份数据，每个更改按顺序保存，保存成功才会广播到各个窗口。

“设置 → 数据与备份”中可以打开数据目录、导出 JSON、导出 Markdown、合并导入、选择自动备份恢复。

- `shinian.json`：当前完整数据。
- `latest-good.json`：最新有效恢复副本。
- `backups/auto-YYYY-MM-DD.json`：每天更新的自动快照，保留最近 14 个日历日。
- `backups/before-*.json`：导入、恢复或载入示例前的保护快照。保护快照不会按 14 天规则自动清理。
- `preserved-corrupt/`：发现损坏时保留下来的原始字节，便于后续分析。

如果当前文件损坏，程序会先保留损坏的原始字节，再尝试有效副本。所有副本都不可用时会明确报错，阻止写入，不会静默重置成空白。磁盘空间不足或权限异常会显示保存失败，编辑器保留待保存的输入。

**本机自动备份不能抵御整块硬盘损坏。** 建议定期导出 JSON 到另一块磁盘或你自己的备份位置。退出前等待“本地已保存”。顶部和快捷记录中的未提交草稿保存在应用自己的缓存中，不属于 JSON 内容备份，重要灵感请点击保存。

导入使用合并策略：保留已有内容；相同备份重复导入不重复创建；有不同修改的内容保留副本；本机外观、快捷键和登录启动设置保持本机选择。恢复自动备份则会用选定快照替换工作区，在确认框中提示，并先备份恢复前的数据。

删除分类只会让里面的内容回到收集箱，包括已完成或已删除内容。父事项完成和子任务完成彼此独立，勾选父事项不会擅自把所有子任务标为完成。

## 当前范围

这版以个人本地工作区为核心。未接入账号、云同步、多人协作、通知服务、自动更新或付费服务。截止日期用于“今日关注”和逾期显示，不会在软件退出后发系统提醒。所有正文字段按纯文本保存，编辑器提供安全的基础 Markdown 预览。单条标题上限 1,000 字符，正文上限 1,000,000 字符；一个工作区 JSON 上限为 64 MiB。达到上限时会拒绝该次保存并保留输入，可先导出并整理内容。

Windows 免安装包已交付；源码也提供 Linux 和 macOS 打包命令，但对应系统的系统集成与签名需要在目标平台验证。完整的实际验证记录见 `docs/VERIFICATION.md`。

## 从源码运行

开发需要 **Node.js 24.x** 和 npm。所有直接依赖与锁文件都已固定版本。

```bash
npm ci
npm run build
npm start
```

如果 npm 所在环境关闭了依赖安装脚本，Electron 运行时不会自动下载，可执行 `node node_modules/electron/install.js` 后重试。

只调整界面时可运行 `npm run dev`，这是带明显提示的浏览器预览，数据在当前浏览器中，与正式桌面数据隔离。生产桌面不允许在桥接缺失时静默回退到浏览器存储。

## 测试与打包

```bash
npm test
npm run build
npm run test:e2e
npm run test:native
npm run test:renderer
npm run package:win
```

Linux 上的桌面自动化测试需要图形环境或 Xvfb，测试默认使用 `DISPLAY=:91`（可通过环境变量改变）。测试中的 `--no-sandbox` 只用于隔离容器运行条件，不会加入实际发行程序的启动参数；发行窗口本身使用 Electron 沙箱、上下文隔离，关闭渲染进程 Node 权限。

`npm run package:win` 生成 Windows x64 免安装 ZIP；也可使用 `npm run package:linux`、`npm run package:mac`，或 `node scripts/package.mjs darwin arm64`。macOS 应在 macOS 上完成签名与公证后再用于常规分发。打包脚本使用 JavaScript，不要求 Windows 开发机安装 Python。

运行时依赖：Electron、React、Lucide 图标、Noto Sans SC 字体。对应第三方许可证已保留在 `THIRD_PARTY_NOTICES.txt`、字体许可证及 Electron 分发资源内。
