## 3. 存储层：18 项单元测试

测试源文件：[tests/store.test.ts](../tests/store.test.ts)。日志结尾明确记录 `tests 18`、`pass 18`、`fail 0`，无跳过或取消。

测试在临时目录执行真实文件操作；失败分支通过替换指定 I/O 调用注入异常。覆盖内容包括：

- 空白初始状态持久化，主文件与恢复副本内容一致，返回值与内部状态分离。
- **48 个并发保存命令**按顺序提交，修订号连续，通知仅在提交后发出，重新打开不丢记录。
- 原子重命名失败、临时文件 `fsync` 失败时保留已确认的内存与磁盘状态，失败后的队列仍可继续使用。
- 主文件已提交而恢复副本更新失败时，报告备份警告，不将已保存记录误报为未保存。
- 主文件损坏时从有效恢复副本恢复，原始损坏字节被保留；主文件和最新副本都损坏时回退到有效日备份。
- 所有恢复来源均无效时，拒绝读取和变更，不以空工作区覆盖现有文件；保留损坏文件失败时也不会跳过保护继续写入。
- 日备份保留最近 **14 个日历日**，忽略无关文件。
- 合并导入、确认恢复之前生成安全备份，修订号保持单调；不合法导入、备份路径和损坏备份不能修改当前数据。
- 系统时钟回拨后仍可恢复合法备份；确认对话框展示后的日备份即使发生更新，也恢复用户当时确认的那份已校验内容。
- 操作前安全备份写入失败时，中止导入或恢复，主数据不变。
- JSON 完整往返、Markdown 导出及受管数据目录防覆盖；原子导出失败时保留已有目标文件。
